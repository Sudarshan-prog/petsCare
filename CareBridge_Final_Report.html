1Executive Summary

CareBridge is a production-ready mobile application built on Flutter that solves one of pet ownership's biggest challenges: finding safe, verified caretakers on demand. The platform creates a trusted ecosystem connecting three distinct groups — Pet Owners, Verified Caretakers, and Adoption Hubs — through a single, intuitive app.

Core Value Proposition: CareBridge uses a proprietary Tiered Trust Verification System to ensure every caretaker listed has been ID-verified, background-checked, and/or NGO-endorsed, giving pet owners peace of mind while creating a reliable income stream for professional caretakers.

The application is written in Dart/Flutter using a clean feature-first architecture with Riverpod state management. The backend is powered entirely by Firebase (Authentication, Cloud Firestore, Firebase Storage, Firebase Messaging) ensuring real-time data sync, scalability, and zero-maintenance server infrastructure.

2Problem Statement

India's pet ownership has grown dramatically, yet pet care infrastructure remains fragmented and untrustworthy. Pet owners face three critical pain points:

# Problem Current Impact
1 Unverified Caretakers No standardized way to vet someone watching your pet; risks of harm or neglect
2 No Proximity Matching Owners cannot easily find nearby caretakers, especially in emergencies
3 Scattered Adoption Services Adoption hubs operate independently; no single platform to browse adoptable pets
4 Zero Emergency Response No platform offers instant access to on-call caretakers for pet emergencies
5 No Pet Wellness Guidance Owners lack real-time, trusted answers to pet health questions
📊 Market Context
India's pet care market is valued at over ₹3,500 crore and growing at 14% CAGR annually. Yet, no app addresses the trust and proximity gap between pet owners and caretakers in Tier 1 and Tier 2 Indian cities.

3Proposed Solution & Value Proposition

CareBridge addresses each problem through a tightly integrated set of features. Instead of building yet another marketplace, CareBridge introduces a Trust-First architecture where caretaker credibility is earned through verifiable milestones before they can accept bookings.

🛡️

Tiered Trust Verification

Three tiers (Verified → Trusted → Pro) unlocked through ID verification, background checks, and NGO partner endorsement. Displayed via visual badges.

📍

Proximity-Based Matching

GPS-based Haversine distance calculation surfaces the nearest available caretakers on a real-time map view, reducing search time from hours to seconds.

🐶

Adoption Hub Integration

Partner NGOs and shelters can list pets (tag: Available / Foster / Adopted) directly on the platform, creating a one-stop discovery experience.

🚨

Emergency SOS System

A dedicated SOS flow instantly shows only on-call caretakers (isEmergency: true), enabling bookings within minutes of a crisis.

🤖

AI Care Assistant (RAG)

A local knowledge-base handles common pet wellness queries; for complex questions, a fallback to Google Gemini API provides expert-grade responses.

💳

Secure Payment (Razorpay)

INR payments with manual capture flow — funds are authorized at booking and only captured when the caretaker accepts, protecting both parties.

5Key Features & Modules

5.1 — Trusted Verification System

The platform's differentiating feature. Every caretaker goes through a progressive trust escalation:

Tier Badge Requirements
Verified 🟢 Green Check ID Scan confirmed (isIdVerified: true)
Trusted 🔵 Blue Shield Verified + Background Check passed (isBackgroundChecked: true)
Pro ⭐ Gold Star Trusted + NGO/Partner Endorsement (isPartnerEndorsed: true)

A Trust Modal pop-up shows users the exact verification checklist for any caretaker before booking.

5.2 — Intelligent Booking Engine

The booking flow spans three steps: Service Selection → Caretaker Discovery → Confirmation & Payment. Caretaker discovery uses Haversine distance calculation to sort results by proximity in real-time. Owners can attach an optional Education Hub flag to any booking, which bundles nutritional and health data with the caretaker request.

5.3 — Emergency SOS

A red-highlighted emergency button on the home dashboard bypasses normal search. It directly queries Firestore for caretakers where isEmergency == true and surfaces them instantly. This is designed so that from SOS button tap to booking confirmation takes under 2 minutes.

5.4 — AI Care Assistant (RAG Architecture)

The wellness chatbot uses a Retrieval-Augmented Generation pattern:

User Query
→
Parse Local knowledge-base.json
→
Confidence ≥ 80%?
→
Answer Locally
Confidence < 80%
→
Gemini API (with CareBridge context prompt)
→
Expert AI Response

5.5 — Push Notifications

Firebase Cloud Messaging (FCM) drives all real-time alerts. Each device's FCM token is stored in the user's Firestore document and refreshed on each session. Booking status changes (Pending → Accepted / Rejected) trigger push notifications to both the owner and caretaker simultaneously.

7Database Design & Security

CareBridge uses Cloud Firestore as a NoSQL document database. Four primary collections store all application state. Security is enforced at the database level via Firestore Security Rules — no unauthorized read or write is possible even if the API keys are publicly exposed.

Data Collections

Collection Key Fields
/users name, email, role, latitude, longitude, profileUrl, fcmToken, phoneNumber
/caretakers name, bio, specialties, price, latitude, longitude, verificationTier, isIdVerified, isBackgroundChecked, isPartnerEndorsed, isAvailable, isEmergency, rating, reviewCount
/bookings ownerId, caretakerId, serviceType, status (pending/accepted/rejected), paymentStatus, isRated, statusImageUrl, createdAt
/pets name, breed, ownerId, status (Available/Adopted/Foster), tags (Vaccinated, Active…)

Security Model (Firestore Rules)

All collections enforce authentication-first access. Key security decisions:

// Bookings — Only owner OR caretaker can read/update their own booking
allow read: if isAuthenticated()
  && (isOwner(resource.data.ownerId)
      || isOwner(resource.data.caretakerId));

// Bookings — New booking must start as 'pending', ownerId must match caller
allow create: if isAuthenticated()
  && request.resource.data.ownerId == request.auth.uid
  && request.resource.data.status == 'pending';

// Users — Can only update own permitted fields (no role escalation)
allow update: if isOwner(userId)
  && request.resource.data.diff(resource.data)
    .affectedKeys().hasOnly(['name', 'phoneNumber', 'latitude', 'longitude', 'profileUrl']);
🔒 Security Highlights
Deletes are disabled on users, caretakers, and bookings collections. Field-level update restrictions prevent privilege escalation. Cloud Functions bypass client rules via Admin SDK for sensitive operations like payment capture.

9Payment Integration (Razorpay)

CareBridge uses Razorpay for all financial transactions in INR (₹). The integration follows a Manual Capture pattern (Blueprint A) which protects both parties from fraud:

Event Payment Action Result
Owner books & pays Payment Authorized (not captured) Money held in escrow; not yet transferred
Caretaker Accepts Payment Captured Funds transferred; caretaker payout triggered via Route API
Caretaker Rejects Authorization Voided Full amount returned to owner; zero platform fees
Post-acceptance Cancellation Refund triggered Refund processed per platform refund policy
Route API: When a booking is captured, a percentage of the payment is automatically transferred to the caretaker's registered Razorpay account (on_hold: true initially, released after service completion). External wallets like Paytm are also supported.
